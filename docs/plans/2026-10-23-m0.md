# GITGUI M0 Implementation Plan

**Goal:** 建立公開 GitHub 專案，以及能安全讀取真實 Git 倉庫的跨平台桌面基礎版本。

**Architecture:** 七專案依賴向 Core 收斂；App 只組裝 DI。status 與 diff 使用 CLI，SHA-1/files 的 log 使用 LibGit2Sharp，其餘格式或函式庫失敗自動使用 CLI。M0 只開放讀取，寫入與網路功能等安全快照完成後再啟用。

**Tech stack:** .NET 8 SDK 8.0.404、Avalonia 11、CommunityToolkit.Mvvm、LibGit2Sharp 0.32、SQLite、Serilog、xUnit、Avalonia.Headless、BenchmarkDotNet。

## 執行順序與驗收

1. [x] 保存原始規格至 `docs/specification.md`，建立七個 src 專案與四個 tests 專案，執行 `dotnet build GitGui.sln`。
2. [x] 在 `tests/GitGui.Core.Tests` 與 `tests/GitGui.Engine.Tests` 先建立失敗測試：格式路由、NUL 路徑解析、真實倉庫、參數安全。再實作 Core 與 CLI，跑 `dotnet test`，提交。
3. [x] 實作 Lib 歷史讀取、三欄 UI、SQLite 最近倉庫與日誌。以 Headless 驗證畫面、以真實倉庫驗證路由與 diff，提交。
4. [x] 設定 Windows/macOS/Linux CI、README、功能進度與安全限制，完整 Release build/test、依賴檢查、Git diff 檢查。
5. [ ] 建立 `linhercherng/GITGUI` 公開儲存庫、推送並確認遠端 commit 與 CI。

## 設計取捨

- 原始文件已指定技術與模組，沿用，不另建替代架構。
- M0 是初始化與唯讀垂直切片；直接一次實作所有 P0 將無法先驗證復原承諾。M1 才逐項啟用寫入。
- 原始文件兩個嵌入式圖表只剩文字標記，未假裝已取得圖表內容。
- 所有 CLI 輸出有容量上限；log 分頁且最多 500 筆。大型倉庫效能目標留待基準測試實測，不視為已通過。
- 原始規格的 .NET 8 升級與授權選擇仍是待辦；公開原始碼不自動代表已授予開源授權。
